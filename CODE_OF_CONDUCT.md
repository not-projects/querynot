# Code of Conduct

## Purpose

QueryNot is an AI-generated software project, but its users, contributors, and maintainers are people. This Code of Conduct defines how we collaborate in issues, pull requests, reviews, release discussions, and project-linked spaces.

We want QueryNot to be clear, respectful, safe, and productive for everyone participating in good faith.

## Expected Behavior

Examples of constructive behavior include:

- Be respectful, patient, and specific.
- Critique ideas, code, and outcomes without attacking people.
- Keep reports and reviews actionable.
- Share relevant context and reproduction details in good faith.
- Protect credentials, private data, and local-first user expectations.
- Review AI-generated material before posting it.
- Correct mistakes openly and without blame.

## Unacceptable Behavior

The following behavior is not acceptable:

- harassment, intimidation, hate speech, or discriminatory language
- personal attacks, insults, or sustained hostile arguing
- publishing or threatening to publish private information
- posting credentials, exploit details, or sensitive user data publicly
- spam, bad-faith reports, or low-effort AI-generated noise
- misrepresenting a contribution's origin, review status, or safety
- conduct that a maintainer reasonably determines makes participation unsafe or unproductive

## Scope

This policy applies to:

- GitHub issues, pull requests, reviews, comments, and project boards
- repository documentation and release material
- project-linked community spaces
- private maintainer communication directly related to QueryNot

## Reporting

Report conduct violations privately to the repository owner, `@tansdf`.

Until a dedicated conduct inbox exists, use a non-public contact method listed on the maintainer's GitHub profile. Include links, screenshots, and immediate safety concerns where possible. Do not post incident details in a public issue.

If no private route is available, open a minimal issue asking for a private reporting channel without describing the incident.

## Enforcement

Maintainers will review reports as fairly and confidentially as practical. Depending on severity and context, they may:

- request a correction or apology
- remove content
- issue a warning
- restrict participation temporarily
- remove a participant permanently

Retaliation against someone who makes a good-faith report is itself a violation.

## Maintainer Responsibilities

Maintainers are responsible for clarifying expectations, applying them consistently, and protecting reporters from retaliation where practical. Not every disagreement is a conduct violation, but maintainers may intervene when behavior makes the project harder to use or maintain.
