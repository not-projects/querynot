# Redesign accessibility evidence

This note records the accessibility evidence gathered for the 2026-08-26 workbench redesign. It is development evidence for the commit containing this file. It does not replace the named native-platform review records under `evidence/phase-5/` and does not expand the release support envelope.

## Automated result

`npm run test:ui-layout` passed the redesigned workbench in Chromium with reduced motion and the checked-in synthetic fixture. The command covers 2048px, 1280px, 960px, and 720px widths; 100–200% UI scale; System, Light, Dark, and Forest themes; keyboard and focus-return behavior for menus, dialogs, tabs, the History drawer, and splitters; and explicit running, rowless, failed, zero-row, filter-empty, and populated result states.

The same run emulates `forced-colors: active` at 1280px and verifies:

- every visible button has an accessible text or ARIA name;
- the focused File command retains a system-visible outline at least 2px wide;
- the accessibility snapshot exposes Connections, File, Results, and the Copy result action;
- the forced-colors workbench has no page-level horizontal overflow; and
- the File command menu remains bounded and keyboard-operable.

The generated `artifacts/ui-layout-report.json` retains the measured forced-colors fields. `artifacts/ui-layout-forced-colors.png` is the corresponding visual review image. The `artifacts/` directory is intentionally local test output and is regenerated by the checked-in command.

1. Run Narrator or Accessibility Insights and inspect the header, Connections and Schema trees, workspace tabs, query editor, Results grid, File and context menus, Export popover, History drawer, and every modal.
